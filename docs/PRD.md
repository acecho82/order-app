# 커피 주문 앱

## 1. 프로젝트 개요

### 1.1 프로젝트명
커피 주문 앱

### 1.2 프로젝트 목적
사용자가 커피 메뉴를 주문하고, 관리자가 주문을 관리할 수 있는 간단한 풀스택 웹 앱

### 1.3 개발 범위
- 주문하기 화면(메뉴 선택 및 장바구니 기능)
- 관리자 화면(재고 관리 및 주문 상태 관리)
- 데이터를 생성/조회/수정/삭제할 수 있는 기능

## 2. 기술 스택
- 프런트엔드: HTML, CSS, 리액트, 자바스크립트
- 백엔드: Node.js, Express
- 데이터베이스: PostgreSQL

## 3. 기본 사항
- 프런트엔드와 백엔드를 따로 개발
- 기본적인 웹 기술만 사용
- 학습 목적이므로 사용자 인증이나 결제 기능은 제외
- 메뉴는 커피 메뉴만 있음

## 4. 프런트엔드 UI

앱은 '주문하기'와 '관리자' 2개 화면으로 구성된다.

### 4.1 주문하기 화면

#### 4.1.1 화면 목적
사용자가 커피 메뉴를 보고, 옵션을 선택해 장바구니에 담은 뒤 주문할 수 있는 화면

#### 4.1.2 화면 구성
화면은 위에서 아래로 다음 3개 영역으로 구성된다.

1. 헤더
2. 메뉴 목록
3. 장바구니

#### 4.1.3 헤더
- 왼쪽에 브랜드명 `COZY`를 표시한다.
- 오른쪽에 `주문하기`, `관리자` 메뉴 버튼을 표시한다.
- 현재 보고 있는 화면의 버튼은 테두리로 강조한다. (주문하기 화면에서는 `주문하기` 버튼이 강조됨)
- 각 버튼을 클릭하면 해당 화면으로 이동한다.

#### 4.1.4 메뉴 목록
- 메뉴는 카드 형태로 가로로 나열한다. (와이어프레임 기준 한 줄에 3개)
- 메뉴 카드에는 다음 항목을 표시한다.

| 항목 | 내용 | 예시 |
|---|---|---|
| 이미지 | 메뉴 사진 | (이미지 영역) |
| 메뉴명 | 굵은 글씨로 표시 | 아메리카노(ICE) |
| 가격 | 기본 가격 | 4,000원 |
| 설명 | 메뉴에 대한 간단한 설명 | 간단한 설명... |
| 옵션 | 체크박스로 선택 | 샷 추가 (+500원), 시럽 추가 (+0원) |
| 담기 버튼 | 장바구니에 추가 | 담기 |

- 예시 메뉴

| 메뉴명 | 가격 |
|---|---|
| 아메리카노(ICE) | 4,000원 |
| 아메리카노(HOT) | 4,000원 |
| 카페라떼 | 5,000원 |

- 옵션
  - 샷 추가: +500원
  - 시럽 추가: +0원
  - 옵션은 여러 개를 동시에 선택할 수 있고, 선택하지 않아도 된다.
- 동작
  - `담기` 버튼을 누르면 해당 메뉴가 선택한 옵션과 함께 장바구니에 1개 추가된다.
  - 같은 메뉴라도 선택한 옵션 조합이 다르면 장바구니에 별도 항목으로 추가한다.
  - 같은 메뉴와 같은 옵션 조합을 다시 담으면 새 항목을 만들지 않고 기존 항목의 수량을 1 늘린다.

#### 4.1.5 장바구니
- 메뉴 목록 아래에 `장바구니` 영역을 표시한다.
- 왼쪽에는 담은 항목 목록을, 오른쪽에는 총 금액과 `주문하기` 버튼을 표시한다.
- 항목마다 다음 정보를 한 줄로 표시한다.
  - 메뉴명
  - 선택한 옵션 (메뉴명 옆에 작은 글씨로 표시, 예: `(샷 추가)`)
  - 수량 (예: `X 2`)
  - 항목 금액 = (기본 가격 + 옵션 가격 합계) × 수량
- 총 금액은 모든 항목 금액의 합계로, 굵은 글씨로 강조해 표시한다.
- 장바구니 내용이 바뀔 때마다 항목 금액과 총 금액을 즉시 다시 계산한다.
- 금액은 천 단위 쉼표와 `원`을 붙여 표시한다. (예: `12,500원`)

- 계산 예시 (와이어프레임 기준)

| 항목 | 계산 | 금액 |
|---|---|---|
| 아메리카노(ICE) (샷 추가) X 1 | (4,000 + 500) × 1 | 4,500원 |
| 아메리카노(HOT) X 2 | 4,000 × 2 | 8,000원 |
| 총 금액 | | 12,500원 |

#### 4.1.6 주문하기
- `주문하기` 버튼을 누르면 장바구니에 담긴 내용으로 주문을 생성한다.
- 주문이 완료되면 장바구니를 비운다.
- 장바구니가 비어 있으면 `주문하기` 버튼을 비활성화한다.

#### 4.1.7 미정 사항
와이어프레임에 나타나지 않아 추후 결정이 필요한 항목
- 장바구니 항목의 수량 변경 및 삭제 기능 제공 여부
- 주문 완료 후 사용자에게 보여줄 안내 방식 (알림 메시지 등)
- 재고가 없는 메뉴의 표시 방식 (품절 표시, 담기 버튼 비활성화 등)
- 장바구니가 비어 있을 때의 안내 문구

### 4.2 관리자 화면

#### 4.2.1 화면 목적
관리자가 전체 주문 현황을 한눈에 보고, 메뉴별 재고를 조정하며, 주문의 처리 상태를 변경할 수 있는 화면

#### 4.2.2 화면 구성
화면은 위에서 아래로 다음 4개 영역으로 구성된다.

1. 헤더
2. 관리자 대시보드
3. 재고 현황
4. 주문 현황

#### 4.2.3 헤더
- 주문하기 화면과 같은 헤더를 사용한다. (4.1.3 참고)
- 관리자 화면에서는 `관리자` 버튼을 테두리로 강조한다.

#### 4.2.4 관리자 대시보드
- `관리자 대시보드` 제목 아래에 주문 상태별 건수를 한 줄로 표시한다.
- 형식: `총 주문 N / 주문 접수 N / 제조 중 N / 제조 완료 N`

| 항목 | 의미 |
|---|---|
| 총 주문 | 전체 주문 건수 |
| 주문 접수 | 상태가 '주문 접수'인 주문 건수 |
| 제조 중 | 상태가 '제조 중'인 주문 건수 |
| 제조 완료 | 상태가 '제조 완료'인 주문 건수 |

- 총 주문은 주문 접수, 제조 중, 제조 완료 건수의 합과 같다.
- 주문이 새로 들어오거나 주문 상태가 바뀌면 건수를 즉시 갱신한다.

#### 4.2.5 재고 현황
- `재고 현황` 제목 아래에 메뉴별 재고 카드를 가로로 나열한다.
- 재고 카드에는 다음 항목을 표시한다.

| 항목 | 내용 | 예시 |
|---|---|---|
| 메뉴명 | 메뉴 이름 | 아메리카노 (ICE) |
| 재고 수량 | 현재 재고 개수 | 10개 |
| `+` 버튼 | 재고 1개 증가 | |
| `-` 버튼 | 재고 1개 감소 | |

- 동작
  - `+` 버튼을 누르면 해당 메뉴의 재고가 1 늘어난다.
  - `-` 버튼을 누르면 해당 메뉴의 재고가 1 줄어든다.
  - 재고는 0 미만으로 내려가지 않는다. 재고가 0이면 `-` 버튼을 비활성화한다.
  - 변경된 재고는 즉시 화면에 반영되고 서버에 저장된다.

#### 4.2.6 주문 현황
- `주문 현황` 제목 아래에 주문 목록을 표시한다.
- 주문마다 다음 정보를 한 줄로 표시한다.

| 항목 | 내용 | 예시 |
|---|---|---|
| 주문 일시 | 주문이 생성된 날짜와 시각 | 7월 31일 13:00 |
| 주문 내용 | 메뉴명과 수량 (옵션 포함) | 아메리카노(ICE) x 1 |
| 주문 금액 | 주문 총 금액 | 4,000원 |
| 상태 버튼 | 주문의 처리 상태 표시 및 변경 | 주문 접수 |

- 한 주문에 메뉴가 여러 개면 주문 내용에 모든 항목을 함께 표시한다.
- 최신 주문이 위에 오도록 정렬한다.
- 주문 상태는 다음 순서로만 진행한다.

```
주문 접수 → 제조 중 → 제조 완료
```

- 동작
  - 새로 들어온 주문의 상태는 `주문 접수`이다.
  - 상태 버튼에는 현재 상태를 표시하고, 버튼을 누르면 다음 상태로 변경한다.
  - `제조 완료` 상태가 되면 더 이상 변경할 수 없으므로 버튼을 비활성화한다.
  - 상태가 바뀌면 관리자 대시보드의 건수도 함께 갱신한다.

#### 4.2.7 미정 사항
와이어프레임에 나타나지 않아 추후 결정이 필요한 항목
- 상태 버튼 문구를 '현재 상태'로 표시할지, '다음에 할 동작'(예: `제조 시작`, `제조 완료`)으로 표시할지
- 주문 시 재고를 자동으로 차감할지, 차감한다면 어느 시점(주문 생성 시, 제조 시작 시)에 할지
- 재고가 적을 때(예: 5개 미만) 경고 표시 여부
- 제조 완료된 주문을 목록에 계속 보여줄지, 숨길지
- 새 주문이 들어왔을 때 화면 자동 갱신 방식 (새로고침, 주기적 조회 등)

## 5. 백엔드

### 5.1 데이터 모델

데이터베이스는 PostgreSQL을 사용하며, 다음 3개 테이블로 구성한다.

#### 5.1.1 Menus
커피 메뉴와 재고 정보를 저장한다.

| 컬럼 | 타입 | 설명 | 예시 |
|---|---|---|---|
| id | SERIAL (PK) | 메뉴 고유 번호 | 1 |
| name | VARCHAR(50) | 커피 이름 | 아메리카노(ICE) |
| description | TEXT | 메뉴 설명 | 깔끔하고 시원한 에스프레소와 물의 조화 |
| price | INTEGER | 기본 가격 (원) | 4000 |
| image_url | VARCHAR(255) | 메뉴 이미지 경로 | /images/americano-ice.jpg |
| stock | INTEGER | 재고 수량 (0 이상) | 10 |

#### 5.1.2 Options
메뉴에 추가할 수 있는 옵션을 저장한다. 옵션은 하나의 메뉴에 연결된다.

| 컬럼 | 타입 | 설명 | 예시 |
|---|---|---|---|
| id | SERIAL (PK) | 옵션 고유 번호 | 1 |
| name | VARCHAR(50) | 옵션 이름 | 샷 추가 |
| price | INTEGER | 옵션 가격 (원) | 500 |
| menu_id | INTEGER (FK → Menus.id) | 연결할 메뉴 | 1 |

- 같은 옵션(예: 샷 추가)을 여러 메뉴에서 쓰는 경우 메뉴마다 별도 행으로 저장한다.

#### 5.1.3 Orders
주문 정보를 저장한다.

| 컬럼 | 타입 | 설명 | 예시 |
|---|---|---|---|
| id | SERIAL (PK) | 주문 고유 번호 | 1 |
| created_at | TIMESTAMPTZ | 주문 일시 | 2026-07-31 13:00:00+09 |
| items | JSONB | 주문 내용 (메뉴, 수량, 옵션, 금액) | 아래 예시 참고 |
| total_price | INTEGER | 주문 총 금액 (원) | 12500 |
| status | VARCHAR(20) | 주문 상태 | received |

- `items` 예시

```json
[
  { "menuId": 1, "menuName": "아메리카노(ICE)", "quantity": 1, "options": ["샷 추가"], "price": 4500 },
  { "menuId": 2, "menuName": "아메리카노(HOT)", "quantity": 2, "options": [], "price": 8000 }
]
```

- `items`의 `price`는 항목 금액 = (기본 가격 + 옵션 가격 합계) × 수량이다.
- 메뉴 이름과 금액은 주문 시점의 값을 그대로 저장한다. 이후 메뉴 정보가 바뀌어도 기존 주문 내용은 바뀌지 않는다.
- `status` 값

| 값 | 화면 표시 |
|---|---|
| received | 주문 접수 |
| in_progress | 제조 중 |
| completed | 제조 완료 |

### 5.2 데이터 스키마를 위한 사용자 흐름

1. **메뉴 조회**: Menus의 내용을 가져와 주문하기 화면에 표시한다. Menus의 정보 중 재고 수량은 관리자 화면의 `재고 현황`에 표시한다.
2. **장바구니 담기**: 사용자가 주문하기 화면에서 커피 메뉴와 옵션을 선택해 담으면, 선택 정보가 장바구니에 표시된다. 장바구니는 브라우저에서만 관리하고 서버에 저장하지 않는다.
3. **주문 저장**: 장바구니에서 `주문하기` 버튼을 클릭하면 주문 정보를 Orders에 저장한다. Orders에는 주문 일시와 주문 내용(메뉴, 수량, 옵션, 금액)을 담는다. 이때 주문한 수량만큼 Menus의 재고를 차감한다.
4. **주문 관리**: Orders의 정보를 관리자 화면의 `주문 현황`에 표시한다. 주문의 기본 상태는 `주문 접수`이며, 관리자가 상태 버튼을 클릭하면 `제조 중` → `제조 완료` 순서로 상태가 변경된다.

### 5.3 API 설계

- 기본 경로는 `/api`이며, 요청과 응답 본문은 JSON 형식을 사용한다.
- 오류 응답은 `{ "message": "오류 내용" }` 형식으로 반환한다.

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/menus` | 커피 메뉴 목록 조회 |
| POST | `/api/orders` | 주문 생성 및 재고 차감 |
| GET | `/api/orders/:id` | 주문 정보 조회 |
| GET | `/api/orders` | 주문 목록 조회 (관리자) |
| PATCH | `/api/orders/:id/status` | 주문 상태 변경 (관리자) |
| PATCH | `/api/menus/:id/stock` | 재고 수량 변경 (관리자) |

#### 5.3.1 메뉴 목록 조회 — `GET /api/menus`
- `주문하기` 화면에 들어오면 데이터베이스에서 커피 메뉴 목록을 불러와 보여준다.
- 각 메뉴에 연결된 옵션 목록과 재고 수량을 함께 반환한다.

```json
[
  {
    "id": 1,
    "name": "아메리카노(ICE)",
    "description": "깔끔하고 시원한 에스프레소와 물의 조화",
    "price": 4000,
    "imageUrl": "/images/americano-ice.jpg",
    "stock": 10,
    "options": [
      { "id": 1, "name": "샷 추가", "price": 500 },
      { "id": 2, "name": "시럽 추가", "price": 0 }
    ]
  }
]
```

#### 5.3.2 주문 생성 — `POST /api/orders`
- 사용자가 커피를 선택하고 `주문하기` 버튼을 누르면 주문 정보를 데이터베이스에 저장한다.
- 요청 본문

```json
{
  "items": [
    { "menuId": 1, "quantity": 1, "optionIds": [1] },
    { "menuId": 2, "quantity": 2, "optionIds": [] }
  ]
}
```

- 처리 순서
  1. 요청한 메뉴와 옵션이 존재하는지, 옵션이 해당 메뉴에 연결된 것인지 확인한다.
  2. 메뉴별 주문 수량이 현재 재고 이하인지 확인한다.
  3. 항목 금액과 총 금액은 클라이언트가 보낸 값이 아니라 데이터베이스의 가격으로 서버에서 계산한다.
  4. Orders에 주문을 `received` 상태로 저장하고, 주문 수량만큼 Menus의 재고를 차감한다.
- 2~4단계는 하나의 트랜잭션으로 처리한다. 중간에 실패하면 주문 저장과 재고 차감을 모두 취소한다.
- 응답: `201 Created`와 생성된 주문 정보 (5.3.3 응답과 같은 형식)
- 오류
  - `400 Bad Request`: 항목이 비어 있거나, 수량이 1 미만이거나, 존재하지 않는 메뉴·옵션을 요청한 경우
  - `409 Conflict`: 재고가 주문 수량보다 적은 경우

#### 5.3.3 주문 정보 조회 — `GET /api/orders/:id`
- 주문 ID를 전달하면 해당 주문 정보를 보여준다.

```json
{
  "id": 1,
  "createdAt": "2026-07-31T13:00:00+09:00",
  "items": [
    { "menuId": 1, "menuName": "아메리카노(ICE)", "quantity": 1, "options": ["샷 추가"], "price": 4500 }
  ],
  "totalPrice": 4500,
  "status": "received"
}
```

- 오류: `404 Not Found` (해당 ID의 주문이 없는 경우)

#### 5.3.4 주문 목록 조회 — `GET /api/orders`
- 관리자 화면의 `관리자 대시보드`와 `주문 현황`에 사용한다.
- 최신 주문이 앞에 오도록 `created_at` 내림차순으로 반환한다.
- 각 주문은 5.3.3 응답과 같은 형식이다.

#### 5.3.5 주문 상태 변경 — `PATCH /api/orders/:id/status`
- 관리자가 상태 버튼을 누르면 주문을 다음 상태로 변경한다.
- 요청 본문: `{ "status": "in_progress" }`
- 상태는 `received` → `in_progress` → `completed` 순서로만 변경할 수 있다.
- 응답: 변경된 주문 정보
- 오류
  - `400 Bad Request`: 순서에 맞지 않는 상태로 변경하려는 경우 (예: `received` → `completed`, `completed`에서 변경)
  - `404 Not Found`: 해당 ID의 주문이 없는 경우

#### 5.3.6 재고 수량 변경 — `PATCH /api/menus/:id/stock`
- 관리자가 `재고 현황`에서 `+`/`-` 버튼을 누르면 재고를 변경한다.
- 요청 본문: `{ "delta": 1 }` (증가는 `1`, 감소는 `-1`)
- 응답: `{ "id": 1, "stock": 11 }`
- 오류
  - `400 Bad Request`: 변경 결과 재고가 0 미만이 되는 경우
  - `404 Not Found`: 해당 ID의 메뉴가 없는 경우
